# Offer Decision Framework — ₹80 Lakh Staff Bar

## Decision rule (default)

**Offer Staff @ ~₹80L only if:**

1. **No round is NO HIRE** on critical dimensions (Rust/coding, system design, security mindset, integrity).
2. At least **three** of these are **HIRE or STRONG HIRE**:
   - Rust + coding
   - System design
   - Distributed systems **or** security/networking
   - Leadership / Staff behaviors
3. Level consensus is **Staff** (not “strong Senior”).
4. HM + bar raiser agree. Bar raiser may veto quality concerns.

**If coding is excellent but leadership is Senior:** offer Senior package / title — do not inflate to Staff for comp optics.

**If leadership is Staff but Rust is shallow:** do not hire for this Rust-primary Staff seat; consider different role only with explicit HM exception.

---

## Mapping votes → outcome

| Pattern | Outcome |
|---------|---------|
| All HIRE+; clear Staff stories | Strong offer; ₹80L in band OK |
| Mostly HIRE; one LEAN on niche topic | Offer possible; note ramp plan |
| Split HIRE / LEAN NO on design or security | Hold / additional round |
| Any ethics issue or cross-tenant blindness | No hire |
| Resume Staff, interview Senior | Senior offer or reject for level |

---

## Comp guidance (Tech HR + HM)

Use as **internal calibration**, not a promise:

| Profile | Guidance |
|---------|----------|
| Clear Staff, scarce Rust + systems + security | ₹80L justified; compete on scope + equity/bonus per band |
| Staff-leaning, one gap (e.g., networking thin) | ₹70–75L or Staff with ramp goals — HM call |
| Strong Senior | Do not use Staff ₹80L; Senior band |
| Principal signals | Different loop / band |

Always follow current Zscaler India compensation bands, leveling committee, and offer approval matrix. This book does **not** override Comp / HR policy.

---

## Pre-offer checklist

- [ ] References (where policy allows) — especially incident ownership & collaboration
- [ ] Expectation set: on-call, security reviews, cross-team work
- [ ] 30/60/90 plan drafted by HM
- [ ] Competing offer timeline handled professionally
- [ ] Written feedback stored; debrief notes complete

---

## 30/60/90 (share after accept)

**30 days:** Codebase + on-call shadow; ship small fix; understand threat model of owned area  
**60 days:** Own a moderate project; first design review led  
**90 days:** Visible cross-team proposal or reliability/security improvement with metrics  

---

## Rejection / hold language (Tech HR)

**Hold:** “We’d like one more deep dive on X to calibrate level.”  
**Reject:** Respectful, timely, no detailed score dump; invite future re-apply if Senior path open.
